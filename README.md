#  OKI  | PARAM Science Core

---

## 🏗️ System Architecture

The project is split into four distinct layers:

### Hardware Layer (`rasp_sockets.py`)
Runs on a Raspberry Pi 5.  
It monitors the UART serial port for RFID scans and broadcasts raw UID data over a WebSocket server.

### Intelligence Bridge (`bridge.py`)
A Flask-SocketIO middleware that manages the visitor lifecycle.

Responsibilities:
- Check-in / Check-out management
- Supabase database transactions
- Communication with Google AI Studio

### The Terminal (`landing.html`)
A high-fidelity cyberpunk-themed HUD for:

- Visitor registration
- Session status
- System feedback

### Deep Analytics (`analytics.html`)
Admin dashboard providing:

- Real-time telemetry
- Visitor demographics
- AI interaction logs

## 🛠️ Installation & Setup

### 1️⃣ Hardware Configuration (Raspberry Pi 5)

Connect the RFID reader to the Pi's UART pins (TX/RX).  
Ensure Serial is enabled using:

```bash
sudo raspi-config
```

Install hardware dependencies:

```bash
pip install pyserial websockets
```

---

### 2️⃣ Bridge Server Setup

Install the server dependencies:

```bash
pip install flask flask-socketio flask-cors requests python-dotenv google-generativeai
```

---

### 3️⃣ Environment Variables

Create a `.env` file in the root directory.

```env
SUPABASE_URL=your_project_url
SUPABASE_KEY=your_anon_key
SERIAL_PORT=COM6
```

For Raspberry Pi / Linux systems:

```env
SERIAL_PORT=/dev/serial0
```

## 🗄️ Supabase Database Schema

The backend uses **Supabase PostgreSQL** to manage visitor sessions and AI interaction logs.

---

### Visitors Table

Stores information about visitors entering the exhibit system.

```sql
create table public.visitors (
  id uuid not null default gen_random_uuid (),
  rfid_uid text not null,
  name text not null,
  age integer not null,
  profile_type text not null,
  check_in timestamp with time zone null default now(),
  check_out timestamp with time zone null,
  constraint visitors_pkey primary key (id)
) TABLESPACE pg_default;
```

**Fields**

| Column | Type | Description |
|------|------|-------------|
| id | UUID | Unique visitor ID |
| rfid_uid | TEXT | RFID card UID |
| name | TEXT | Visitor name |
| age | INTEGER | Visitor age |
| profile_type | TEXT | Visitor profile category |
| check_in | TIMESTAMPTZ | Time visitor checked in |
| check_out | TIMESTAMPTZ | Time visitor checked out |

---

### Messages Table

Stores all interactions between the visitor and **OKI AI** during the voyage session.

```sql
create table public.messages (
  id bigint generated by default as identity not null,
  voyage_id text null,
  visitor_id uuid null,
  rfid_uid text null,
  name text null,
  age integer null,
  profile_type text null,
  user_query text null,
  oki_response text null,
  timestamp timestamp with time zone null default now(),
  constraint messages_pkey primary key (id),
  constraint messages_visitor_id_fkey foreign KEY (visitor_id) references visitors (id)
) TABLESPACE pg_default;
```

---

### Index for Voyage Queries

Optimizes retrieval of message logs for a specific voyage session.

```sql
create index IF not exists idx_messages_voyage
on public.messages using btree (voyage_id)
TABLESPACE pg_default;
```

---

### Relationship

```
visitors (1) ──────── (many) messages
```

- Each **visitor** can generate multiple **messages**
- Messages are linked using **visitor_id**
- `voyage_id` groups interactions into a single exhibit session

---


Visitor interactions are processed by Gemini 1.5 Flash and logged for analytics.

### 5. Termination
A second RFID tap triggers the Check-Out sequence and clears the session.
